## Key Changes

Closes three owner-reported gaps in the Menu Design system that the existing
504/506/508 granularity did not cover — a **floating-header scroll transition**
(different bg/border/shadow once scrolled), a **floating-card menu bar**
(level-0 border-radius + a custom `box-shadow` beyond the none|sm|md preset
enum), and a richer **brand mark** (a named lucide icon mode + an image/icon
graphic-WITH-text combo). All three land as **present-only, additive,
jsonb-only** extensions on the existing validated `PATCH /menus/:id` document
write path: **NO DDL, NO migration, NO `MENU_DOCUMENT_SCHEMA_VERSION` bump**
(stays `1`), **NO new route/RBAC, NO new npm dependency**. Every legacy /
no-override menu document parses and renders **byte-identical**, and
`buildSiteShellCss(null)` is untouched (the new keys never join `MenuAppearance`/
`SHELL_APPEARANCE_DEFAULTS`). Landed strictly in order 520-01 → 520-02 → 520-03 →
520-04 → 520-05 (disjoint single-writer file ownership).

- **Menu-bar + brand MODEL (520-01, `core/services/menus/menuDocumentV2.ts`):**
  a NEW sibling allowlist `MENU_BAR_EXTRA_KEYS` gates six non-appearance bar keys
  as an intersection extension of `MenuBarLayout` (NOT `MenuAppearance` members,
  held OUT of `MENU_BAR_LAYOUT_KEYS`/`SHELL_APPEARANCE_DEFAULTS` ⇒ no seeded
  resolver default): `radius` (0..40 px, `MENU_BAR_LAYOUT_NUMBER_RANGES.radius`),
  `shadowCustom`, `surfaceColorScrolled`/`borderColorScrolled` (`normalizeMenuColorValue`,
  alpha OK), `borderWidthScrolled` (0..8), `shadowScrolled` (none|sm|md) and
  `shadowCustomScrolled`. `normalizeMenuBarLayout` is SPLIT — appearance keys via
  `normalizeAppearanceSubset`, extra keys via local fail-soft value normalizers;
  a key in NEITHER allowlist throws `MenuDocumentError(path.key)`, bad VALUES
  fail-soft (omit). `shadowCustom` OVERRIDES the `shadow` enum and
  `shadowCustomScrolled` OVERRIDES `shadowScrolled` at emission; an unset scrolled
  variant falls back to the corresponding BASE key (back-compat). `BrandProps.mode`
  widens to `"text" | "image" | "icon"`; `BRAND_PROP_KEYS` gains `"icon"`/`"showText"`,
  `BRAND_STYLE_KEYS` gains `"iconColor"`/`"iconSize"`, `BRAND_STYLE_NUMBER_RANGES`
  gains `iconSize [12,64]`.
- **Custom box-shadow validator (520-01-L02, security-critical).** NEW
  `normalizeMenuBoxShadowValue` accepts ONLY a bounded, BRACKET-AWARE grammar:
  optional leading `inset`, ≤4 length values (`-?\d+(px|rem|em)`), and ONE color
  token validated via `normalizeMenuColorValue`, comma-repeated to ≤4 layers,
  total ≤200 chars; whitespace is split only at bracket-depth 0 (so
  `rgba(0,0,0,.24)` is ONE token) and leading-dot alpha is canonicalized
  consistent with TASK-519. REJECTS any `url(`/`expression(`/`javascript:`/
  `image-set(`/`/*`/`<`/`>`/`{`/`}`/`;`/`@`/backslash or off-grammar token.
- **Brand icon-name validator (520-01-L03, allowlist).** `normalizeBrandIconName`
  pattern-checks a kebab lucide name (`^[a-z0-9-]{1,64}$`, fail-soft omit); the
  RENDER resolves it against `lucideKebabIconComponents` (the lucide set = the
  effective allowlist), so an unknown/unresolvable name falls through to the
  text/site-name chain (never a broken/injectable mark).
- **Menu-bar CSS emission (520-02, `core/site/menuDocumentCss.ts`):** emits the
  level-0 `border-radius`, the custom shadow (overriding the enum), and a NEW
  `[data-scrolled="true"]` selector block carrying the scrolled-variant
  bg/border/shadow — all from validated stored values only; per-device via the
  existing `resolveMenuSectionAppearanceForDevice(...).layout` channel; zero bytes
  when unauthored.
- **Design Editor controls (520-03, `core/admin/ui/menus/MenuDesignEditor.tsx`):**
  a bar scrolled-state group (colors via TASK-519's alpha-capable
  `ColorSwatchControl`) gated on `sticky`, a radius slider, a custom-shadow text
  control (fail-soft empty on drop), and a preview "scrolled" toggle that stamps
  `data-scrolled` on the canvas; a brand mode selector (`text|image|icon`) with an
  icon picker + `iconColor`/`iconSize` + a `showText` combo toggle. The new bar
  keys render NO `ControlDefaultHint` (they resolve to `value===undefined` ⇒ the
  507 guard hides the hint) and use static helper text instead.
- **FRONT render (520-04, `core/site/siteShell.tsx`):** `BrandRender` extends from
  `<img>` XOR text to also render a resolved lucide icon (via
  `lucideKebabIconComponents`, colored/sized by `iconColor`/`iconSize`) AND the
  graphic-WITH-text combo (graphic + wordmark side by side when `showText:true`);
  a tiny dependency-free idempotent inline IIFE (respects `prefers-reduced-motion`)
  toggles `data-scrolled` on the header past a small threshold — emitted ONLY when
  a scrolled variant is authored AND the bar is sticky (a legacy/non-sticky/
  no-variant doc emits NO script).
- **Security (defence in depth).** Colors run through `normalizeMenuColorValue`;
  custom shadows through the new bracket-aware `normalizeMenuBoxShadowValue`; the
  brand icon name through a pattern allowlist at write AND lucide-set resolution at
  render (never interpolated into markup). Each new key joins its reject-unknown
  allowlist + ships a persistence round-trip test (fail-closed READ trap). Bad
  VALUES fail-soft (omit), never throw; only an unknown KEY 400s with a `path`.
- **Docs:** `_docs/PAGE_MODEL.md` (menuDocumentV2 — the new `MenuBarLayout` keys,
  validators, `BrandProps`/`BrandStyle` icon/combo, scroll-state machine) and
  `_docs/CONTENT_TYPES_SPEC.md` (the Design-tab authoring surface + security
  whitelist notes) updated.
- **Tests:** per-subtask unit lanes (Vitest `menu-document-v2.test.ts` model

  `normalizeBrandIconName` tables; Bun `menu-document-render.test.tsx` CSS/render
  + `BrandRender` icon/combo + scroll-machine script; Vitest
  `menu-design-editor.test.tsx` bar/brand controls + `ControlDefaultHint`-absent);
  520-05 adds the Bun route lane (`tests/integration/routes/menus.test.ts`):
  new bar + brand keys persist per-key without dropping siblings, an unknown bar
  key 400s with `menu_document_invalid` + `path`, and the SECURITY negatives
  (injection shadow / `url()` color / path-traversal icon) fail-soft DROP on write
  so the stored doc round-trips WITHOUT them. All gates green (`bun --cwd core
