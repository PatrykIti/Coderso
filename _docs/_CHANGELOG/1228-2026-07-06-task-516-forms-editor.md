## Key Changes

Brings the **Forms** editor (`core/admin/ui/forms/**`, services
`core/services/forms/**`, routes `core/server/routes/formsRoutes.ts`, public
widget `core/widgets/core/formEmbed.tsx`) to prototype fidelity
(`_docs/_PROTOTYPE/src/pages/advanced/FormBuilderPreview.tsx`), fixes the
enumerated broken/hidden field controls, adds a **whole-form style/theme model**
stored in the existing `forms.settings` **jsonb** column (**NO DB migration**),
and adds the **`file` field type** with a NEW public nonce-gated upload route.
The form theme applies consistently across the builder canvas, the runtime
preview, and the public `form-embed` rendering. Landed strictly in order
516-01 → 516-02 → 516-04 → 516-03 → 516-05 → 516-06 → 516-07 (single-writer file
ownership; the only multi-writer exception is 516-07's additive `file`-case-only
seam, landing last).

- **Form theme/style model + resolver (516-01):** new `forms.settings.theme`
  sub-record (`layout`/`surface`/`typography`/`input`/`submit`) normalized
  **present-only + reject-unknown** in `formSettings.ts` (`normalizeFormTheme`:
  each branch rebuilt field-by-field, unknown keys dropped, out-of-enum values
  omitted). A no-theme form emits **no** `theme` key while the four base keys
  stay present (the normalizer is fully-defaulted, NOT a passthrough). New
  `core/services/forms/formTheme.ts` is the ONE source of truth: shared enum
  unions/`FORM_THEME_*` Sets (`sm|md|lg|xl|full` widths, `none|sm|md|lg|xl` radii,
  `none|soft|sm|md|lg` shadows, `display|inherit|sans|serif|mono` fonts, etc.),
  the `FormFormTheme` type, and `resolveFormTheme(theme)` → fully-defaulted
  GROUPED-RAW `ResolvedFormTheme` (enum/bool tokens concrete, color tokens
  undefined by default) plus token→className maps + `buildFormThemeStyleVars`.
  `resolveFormTheme(undefined)` reproduces the prototype card exactly. Colors run
  through `resolveClearableCssColorValue` at BOTH the normalize (write) and render
  boundaries (defence-in-depth). `formsClient.ts` mirrors the theme on its
  `FormSettings` type for round-trip.
- **Design inspector panel (516-02):** new `core/admin/ui/forms/FormDesignPanel.tsx`
  renders grouped Layout / Surface / Typography / Inputs / Submit sections using
  the same clearable-style color-swatch controls the widget editors use. Every
  control shows the resolved default (`resolveFormTheme(undefined)`) as its
  hint/placeholder and has a reset-to-default affordance. `onThemeChange` emits a
  present-only GROUP-LEVEL `Partial<FormFormTheme>` (unset control → key absent);
  clearing the last token emits `undefined` (drops the whole theme → no `theme`
  key persisted).
- **Builder chrome + rail fidelity (516-03):** replaced the full-screen
  `EditorShell` with the in-page `PageHeader` (breadcrumbs `Forms › {name}`,
  Save + **Publish** actions) + `EditorFrame` (chrome bar / left rail / canvas /
  right inspector). Right-aligned toolbar `actions` carry a status badge, the
  functional **desktop/mobile device toggle** (drives canvas width), and
  render-only **disabled undo/redo** chrome (functional edit-history is explicitly
  out of scope). `FieldLibrary` now uses `EditorRailGroup`/`EditorRailItem` and
  exposes **Phone** (fixes B1 — phone was end-to-end supported but unreachable in
  the library). Removed the redundant `Fields`/`Library` tab split — a single
  library rail on the left, field selection via canvas-click; deleted the
  `fieldListItems` memo + both `FieldListPanel` render sites (the standalone
  `FieldListPanel.tsx` is left UNCHANGED as a test-covered primitive). The Design
  tab is mounted into the inspector tab set.
- **Canvas fidelity + preview fixes (516-04):** `FormCanvas.tsx` gains optional
  `theme?`/`deviceWidth?` props (landed before 516-03 wires them) and applies
  `resolveFormTheme(theme)` to the canvas card + fields; `deviceWidth` sets the
  frame width. Added a real `<select>` preview branch (fixes **B2** — `select`
  previously fell through to a text input) and type-specific affordances for
  `date`/`time`/`number`/`phone`/`email` (fixes **B3**); `rating` maps to a scale
  affordance instead of the range slider (fixes **B5** low-fidelity). Column/width
  precedence documented: form theme `layout.columns` is the default grid, a
  field's own `style.width` overrides for that field.
- **Field settings control fixes (516-05):** `FieldSettingsPanel.tsx` +
  `fieldSettings.ts` — added `time` to the step-supporting set so the increment
  control shows (fixes **B4**); removed the inert Minimum control for `rating`,
  keeping a scale (3–10) max control (fixes **B5**); `phone` control gating with
  no dead controls (**B1**); inline required-hint on the `hidden` field's
  defaultValue before save (fixes **B6**).
- **Runtime theme application (516-06):** `FormRuntimePreviewDialog.tsx` and the
  public `formEmbed.tsx` now INHERIT the form theme via `resolved.settings.theme`.
  `pageRendererV2` `mapFormBindingToEmbedData` (per-region single-writer) adds the
  present-only `theme` passthrough (the projection previously dropped `theme`, so
  the public embed rendered un-themed). Precedence: form theme = BASE, per-embed
  `FormEmbedStyle` OVERRIDES per explicit token (enum value mapping such as
  `left→start`, clamp of extra values such as `radius:"xl"→"lg"`,
  `titleWeight:"normal"→"medium"`, and direct container/grid apply for tokens with
  no widget enum). All theme-derived colors still pass
  `resolveClearableCssColorValue` at render; the existing raw `borderColor` seam is
  not widened to theme input.
- **`file` field type + public upload route (516-07):** registered `file` in the
  field-type union + `validation.normalizeSettings` (per-field `accept` MIME
  allowlist with `image/*` wildcards, `maxSizeMb` clamped `1..100`, `multiple`).
  New public **`POST /forms/:id/uploads`** (`handleFormAttachmentUploadRoute`)
  reuses the form's OWN submission access gate (submission-access evaluator,
  runtime form nonce, `public_write` rate-limit keyed by form id, bot protection)
  — NOT `media:write` — and enforces the field's `accept`/`maxSizeMb` via a new
  `mediaService.uploadMedia` `constraints` param; anonymous uploads content-sniff
  the actual bytes. New `formAttachmentUploadSchema` (`additionalProperties:false`)
  and two NEW leaf modules: `core/services/forms/mimeMatchesAccept.ts` (shared
  dependency-free wildcard predicate that breaks the media↔forms cycle) and
  `core/services/forms/formAttachment.ts` (`verifyFileReferences` DB-backed
  submission backstop). Submitted `file` values are accepted only as owned media
  ROW ids (or id arrays); `submissionService` normalizes then `verifyFileReferences`
  re-resolves each id via `getMediaById`, rejecting unknown/cross-origin ids, wrong
  MIME, or oversize as `form_payload_invalid`. Client-supplied paths/URLs are never
  trusted. Uploaded rows are tracked with a new `"submission"` media-usage variant
  (`mediaUsageService.ts` `form_submissions` scan branch). Additive `file`-case-only
  UI edits to the rail/canvas/embed/runtime-preview complete the seam.
- **NO DB migration.** The theme lives in the existing `forms.settings` jsonb; the
  `file` field references existing media rows rather than adding a table (a
  dedicated per-form upload store is an explicit follow-up).
- **Security:** theme colors policy-checked at normalize + render via
  `resolveClearableCssColorValue`; `file` submissions validated as owned media
  references with size/MIME/reject-unknown guards on the public path. Docs synced:
  `CMS_API.md` (Forms `settings.theme`, `file` field, `POST /forms/:id/uploads`),
  `SECURITY_SPEC.md` (file field/upload route + theme-color render-path policy),
  `_WIDGETS/FORM_EMBED.md` (theme inherit + `file` supported type).
- **Tests:** theme normalize/reject-unknown/clamp/round-trip/present-only-no-theme
  (`formSettings`/`formsService`), `formTheme` resolver + token→class maps,
  `FormDesignPanel`/`FormCanvas`/`FieldSettingsPanel`/`FormRuntimePreviewDialog`
  render assertions, `formEmbed`/`formRuntimeResolver` theme inherit + per-embed
  override precedence, and file upload route security (size/MIME/reject-unknown,
  media-usage tracked, owned-reference submission rejection). All gates green
  (`bun --cwd core lint`/`lint:types`, root `tsc`, `bun run test:bun`,
  `bun run test:vitest`, `gates:coderso`). The ≥5-scenario LIVE prototype-fidelity
  Playwright smoke is run by the orchestrator post-merge (the dev host serves the
  MAIN tree, not this worktree).
