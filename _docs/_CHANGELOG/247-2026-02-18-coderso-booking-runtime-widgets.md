## Key Changes

### Core/API
- Added public booking runtime endpoints:
  - `GET /api/booking/slots`
  - `POST /api/booking/reservations`
- Hardened `GET /api/booking/slots`:
  - requires signed `runtimeToken` (HMAC, short TTL),
  - token is generated by booking runtime resolver and injected into widget payload.
- Added public booking payload validation schemas for slots query and reservation submit.
- Added public booking runtime handler with:
  - domain error mapping (`booking_*`),
  - public read/write rate-limit bucket usage,
  - submission nonce guard,
  - bot protection (`public_write`) enforcement when enabled.

### Services
- Added booking runtime resolver that hydrates active services/resources and submission nonce for SSR/runtime widgets.
- Added booking nonce bridge service (`createBookingSubmissionNonce`, `assertBookingSubmissionNonce`) reusing existing form nonce primitives.

### Widgets
- Added new core widgets:
  - `booking-calendar`
  - `appointment-form`
- Added shared runtime script (`bookingRuntimeScript`) with `flowId`-based event bridge:
  - calendar publishes selected slot,
  - appointment form consumes selected slot and submits reservation.
- Added widget editor implementations (Wizard/Visual/Advanced) for both widgets.
- Registered widgets in admin and runtime registries.

### Runtime SSR
- Public runtime hydration now resolves booking payload once per render pass and injects into booking widgets.
