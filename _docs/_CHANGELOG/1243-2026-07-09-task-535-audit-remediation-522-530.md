## Key Changes

Post-merge audit remediation for the Page v2 composable-effects program
(TASK-522…530). All fixes are **present-only / jsonb-only**: NO npm dependency,
NO DB migration/DDL, NO `PAGE_DOCUMENT_SCHEMA_VERSION` bump (stays `2`), NO
route/RBAC change. Every path a page without the relevant effect touches
normalizes AND renders **byte-identical** to pre-535; `prefers-reduced-motion`
gates are unchanged.

### HIGH — tilt + layer containing-block regression (correctness)

- **`splitBlockComposition` / `renderPageBlockWithFrame` (`pageRendererV2.tsx`) +
  `pageResponsiveCss.ts`.** A block authoring BOTH `tilt` AND `style.layer`
  rendered the layered chip in the WRONG place. The 528 tilt fix wraps a tilted
  frame in a `[data-tilt-parent]` `perspective:1200px` wrapper; a non-`none`
  `perspective` establishes a **containing block** for absolutely-positioned
  descendants, so the layer CSS
  (`[data-composition="layered"] [data-layer]{position:absolute;left:var(--layer-x)…}`)
  made the FRAME resolve its `--layer-*` offsets against the WRAPPER (at its
  in-flow origin) instead of the `.cx-layered-canvas` — regressing
  TASK-522-05-L02. **Fix:** hoist the LAYER PLACEMENT (`data-layer` +
  `data-layer-anchor` + base `--layer-x/y/z`) onto the wrapper so the WRAPPER is
  the absolutely-positioned layered child (offsets resolve against the canvas;
  the 524 anchor `translate:` rides the wrapper), while the tilt transform stays
  on the inner frame. The split fires ONLY when tilt AND layer are BOTH authored
  (`hoistLayerToWrapper`); every other combo keeps the placement on the frame,
  byte-identical.
- **Per-device layer override retarget.** CSS custom props inherit DOWNWARD only,
  so a per-device `--layer-*` override on the child `[data-block-id]` frame could
  never reach the wrapper that now consumes `var(--layer-*)`. The renderer stamps
  `data-tilt-parent-for="<block-id>"` on the wrapper ONLY for the hoisted
  tilt+layer case (new `PAGE_TILT_PARENT_LAYER_ATTRIBUTE`); `collectBlockDeclarations`
  routes the per-device layer offsets to a new `wrapper` bucket targeting
  `[data-tilt-parent-for="<id>"]` when the base style is tilt+layer, else keeps
  them on the frame (`layer-only` case byte-identical). `data-block-id` stays
  uniquely on the frame (selection chrome depends on the 1:1 mapping).

### MEDIUM

- **Reveal `--reveal-delay` inheritance double-bind (`PAGE_REVEAL_MOTION_CSS`,
  `pageRendererV2.tsx`).** `--reveal-delay` is a custom property, which INHERITS.
  A container authoring `revealDelay` set it on its own frame, so a NESTED CHILD
  block that authored NO delay would INHERIT the ancestor's value and cascade at
  the ancestor's delay (all children of a delayed container animate together,
  defeating per-block stagger). **Fix:** reset `--reveal-delay:0ms` in the same
  per-frame stylesheet rule under `[data-reveal-armed] [data-page-effect^="reveal"]
  [data-page-block]`; an AUTHORED block's INLINE var beats the author-stylesheet
  declaration (inline wins the cascade) so it keeps its value, an UNAUTHORED
  descendant no longer inherits an ancestor's delay. Pure CSS (no `@property`);
  the inline frame emit is untouched.
- **Full-bleed horizontal-scroll overflow guard (`pageRendererV2.tsx`).** A
  full-bleed section paints a `width:100vw` bleed box; `100vw` counts the
  vertical-scrollbar gutter, so on a scrolling page it is a few px WIDER than the
  content area and pushed a spurious HORIZONTAL scrollbar. Present-only guard:
  `overflowX:"clip"` on the page root when `docHasFullBleedSection(...)`. `clip`
  (NOT `hidden`) is deliberate — `overflow:hidden` on one axis forces the other to
  `auto`, establishing a scroll container that BREAKS `position:sticky`
  descendants (the front sticky nav); `clip` clips without creating a scroll
  container so sticky keeps working. Per-document (the footer wraps its own bleed
  sections in its own root). A page with no full-bleed section keeps `rootStyle`
  byte-identical.
- **`baseSectionClassName` full-bleed predicate mismatch (`pageRendererV2.tsx`).**
  The section utility-gutter className keyed off ONLY the `full-width` template
  variant, while the bleed box + content cap already keyed off the shared
  `isPageSectionFullBleed(...)` (variant OR the author-toggled `style.fullBleed`).
  A `style.fullBleed`-only section therefore got its 100vw bleed box AND still
  carried the `px-4 py-6` utility gutter (doubled padding, content not truly
  edge-to-edge). **Fix:** route the className off the SAME predicate. Non-full-bleed
  keeps `w-full px-4 py-6` byte-identical.
- **Stale `not_css_expressible` diagnostic for full-bleed `maxWidth`
  (`pageResponsiveCss.ts`).** The 525 model DECOUPLED the bleed box from the
  content cap (the pre-525 `max-width:none` pin is GONE — full-bleed content is
  always capped/centered at `layout.maxWidth`), so a responsive `layout.maxWidth`
  override IS now CSS-expressible on a full-bleed section. `collectSectionDeclarations`
  no longer emits the stale `not_css_expressible` diagnostic; instead it mirrors
  the base content div — a full-bleed section gets BOTH `width:min(<max>,
  calc(100% - 2 * 20px))` AND `max-width:<max>` (mirrored predicate + gutter,
  re-declared here with a MUST-stay-in-sync note to avoid a back-import cycle).
  Non-full-bleed keeps the plain `max-width` declaration byte-identical.
- **Two-document spotlight overlay double-stack (`pageRendererV2.tsx`,
  `siteShell.tsx`, `pageRuntimeV2.tsx`).** A page renders TWO `PageDocumentRender`
  documents — the `<main>` page (primary) and the `SiteFooter` template
  (secondary) — each authored independently, so BOTH can author motion. The
  viewport-fixed spotlight OVERLAY DIV (`fixed inset-0` `mix-blend:screen`) is a
  true page-global SINGLETON: two copies stack another radial-gradient and DOUBLE
  the brightness. **Fix:** emit the overlay EXACTLY ONCE per page
  (`emitsSpotlightOverlay`) — the primary owns it when EITHER document authors
  spotlight (`spotlightOn || peerSpotlightOn`), the footer owns it only for a
  footer-only spotlight (`spotlightOn && !peerSpotlightOn`). Threaded via new
  `documentRole` / `peerSpotlightOn` props (`documentUsesSpotlight` export) from
  `DefaultRuntimePageShellV2` → `SiteFooter` → `PageDocumentRender`. The
  idempotent effect STYLESHEETS (reveal/composition/spotlight CSS + reveal
  noscript) stay PER-DOCUMENT / present-only so a FOOTER-ONLY effect is still
  styled (an earlier 535 pass that gated them primary-only was reverted — it
  suppressed them on BOTH documents for footer-only effects).
- **Runtime double-init (`pageEffectsRuntime.ts`).** The same runtime `<script>`
  can be emitted twice (main + footer document each emit their own when they
  author motion); both share one `window`. Without a guard the second copy would
  re-arm reveal, double-bind scroll/pointer listeners and re-observe the same
  nodes. **Fix:** the IIFE self-guards on a window init flag
  (`PAGE_EFFECTS_RUNTIME_INIT_FLAG = "__codersoPageMotionEffectsInit"`) — the
  FIRST executable statement sets the flag and any later copy returns early (total
  no-op). The static source hardcodes the same key literal (invariant #1 forbids
  interpolating a value into the source); the export lets consumers/tests
  reference the exact key without drift.

### SVG sanitizer hygiene (`svgSanitizer.ts`) — defence-in-depth

- **Case-insensitive root vs case-sensitive walk mismatch.** The root gate
  (`/^<svg[\s>]/i`) admitted an uppercase `<SVG>` whose tags the case-SENSITIVE
  walk then DROPPED, leaking the allowlisted CHILDREN as an UNWRAPPED fragment.
  **Fix:** `ALLOWED_TAG_CANONICAL` (case-insensitive lookup → canonical spelling);
  the walk re-emits the canonical form, keeping camelCase tags
  (`linearGradient`, `feGaussianBlur`, `clipPath`) intact and preserving the
  allowlist invariant.
- **Self-closing root + trailing-junk bypass.** Accepts a valid self-closing
  `<svg …/>` root, but FAIL-CLOSED when a self-closed `<svg/>` is followed by junk
  and a trailing `<svg>…</svg>` (which would pass the start + `</svg>`-end gates
  while leaving un-walked verbatim text): the FIRST `<svg…>` must be an OPEN tag,
  else reject.
- **Valueless/boolean attr leak + unbalanced-quote residue.** The attr rebuild now
  keeps ONLY allowlisted `name=value` pairs (a valueless `<rect fill-rule>` /
  `autofocus` is left out, not passed through verbatim), and `TAG_REEMIT_RE`'s attr
  body is a QUOTE-BALANCED class (not a loose `[^<>]*`) so an unbalanced-quote tag
  is left in the residue and trips the fail-closed residual-`<` / odd-quote guard
  instead of being silently stripped (which would leak a raw `style`/clickjacking
  attr). Self-closing tags are preserved (`selfClose` captured + re-emitted).

### Render-parity re-sanitize (`pageCompositionEffects.tsx`) — defence-in-depth

- `resolveBlockCompositionAttrs` (`--surface-glow`/`--deco-ring`/`--orb-color`
  from `surfaceTint`/`background`) and `resolveSectionCompositionAttrs`
  (`accent`) run at RENDER and thread the value straight into a `style` custom
  prop. They now `sanitizeAuthoringCssColor(...)` at render exactly as the
  spotlight color / canvas background already do — a write-sanitized plain color
  passes unchanged (behaviour identical for valid input), an unexpected value
  drops the glow (present-only). Also removed the now-dead
  `[data-tilt-parent]{perspective:1200px}` CSS rule (the perspective is an inline
  style on the wrapper since 528).
