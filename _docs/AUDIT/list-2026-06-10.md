## 4. Functional checks
- **Canvas WYSIWYG:** `canvasRedAfterBgSet=1`. Section background `#ff0000` paints red on the canvas. TASK-417 BROKEN → now **FIXED**.
- **Block real render vs placeholder (default empty list):** the published front for the default (empty-items) list showed **"This page has no content yet."** with `sectionTypes=[]`, `blockTypes=[]`. Inspecting the stored page detail API revealed `currentData.sections=[]` AND `publishedData.sections=[]` — **the section/block was pruned on save** because the only block was a content-empty list. So an empty list block does NOT survive save → empty page on the front.
- **Block real render vs placeholder (populated list — extra check):** created a second page, set Items=`Alpha, Beta, Gamma` immediately after insert, saved + published. Stored `publishedData.sections=1` with `blocks=[{type:list, items:["Alpha","Beta","Gamma"]}]`. Front rendered a **real** `<ul class="list-disc ...">` with three `<li>` (Alpha/Beta/Gamma), `blockTypes=[list]`, `placeholderHits=[]`. So a populated list persists and renders correctly.
- **Ordered toggle:** functional at data level via the yes/no select; not exercised on the front in this run.
- **Note (environmental):** the very first Publish after a mid-session editor reopen surfaced a transient "Invalid CSRF token" toast and left the page `draft`; a subsequent Save (which refreshed the token) + re-Publish succeeded. This is a stale-CSRF artifact of the audit's manual navigation, not a list-specific defect.

## 6. Floating-panel drift vs reference
- **`Ordered` is a native yes/no `<select>`** instead of the reference `.sw` toggle — the list's defining control gap.
- **No .seg pill groups** — Width, Align, Shadow, Background type are native `<select>`.
- **No .swatch color swatches/picker** — Text color, Border color, Background color are raw-hex text inputs.
- **No .slider range** — Radius is a number input.
- **No .sw toggle** — Visible is a yes/no `<select>`.

## 7. Verdict
**PARTIAL** · severity **medium** — a populated list inserts, persists, and renders a correct `<ul>/<li>` on the front. Two issues: (1) inspector drift — zero dedicated controls (`switch=swatch=slider=segmentedGroup=0`), and specifically the registry's `ordered: switch` renders as a yes/no `<select>`; (2) a content UX trap — the **default empty list is pruned on save**, so a freshly inserted list (before the author types items) yields an empty "no content yet" page on the front. Low-severity data-integrity edge, but worth flagging since the default-inserted state silently disappears.
