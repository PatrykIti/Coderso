## Overview

Add a collection-level admin workspace that lets users manually inspect and edit
the resources generated by the blueprint composer.

This workspace is the UI frame over the collection. It does not replace existing
Page Editor, Entries, Custom Screens, Listings, Forms, SEO, or route editors.
It reuses them and provides one coherent place to understand how the collection
is wired.

Example collection: `House Projects`.

The workspace should show:

- content model fields,
- entries/records,
- public list/landing page,
- detail page template,
- listing query and card template,
- filters/facets,
- forms and CTAs,
- custom admin screen,
- SEO and route patterns,
- preview/open public URL actions,
- readiness and diagnostics.

## Manual Editing Flow

Detail template editing should work like this:

```text
open Collection Workspace
  -> Detail Template tab
  -> select sample entry
  -> edit blocks through Page Builder shell in detail-template mode
  -> bind widget props to fields using binding panel
  -> validate bindings and secret/public safety
  -> preview /:slug runtime with sample entry
  -> save draft
  -> publish detail template
```

The Page Builder shell should run in `detail-template` mode:

```ts
type BuilderSurfaceMode = "page" | "widget-template" | "custom-screen" | "detail-template";
```

Detail-template mode differences:

- block data can contain binding placeholders,
- selected block inspector includes a `Bindings` panel,
- preview requires a sample entry,
- save target is `detail_page_documents`, not `pages`,
- publish affects public detail runtime for the collection.

## Security Contract

- Visibility: internal admin UI only.
- Auth model: authenticated admin session.
- RBAC:
  - read requires current content/page/listing/form/seo read permissions,
  - write requires the write permission of the edited resource family,
  - publish detail template requires content/page publish permission because
    detail pages are a public runtime surface.
- CSRF: all mutations go through existing internal admin/assistant endpoints.
- Rate-limit bucket: `admin_read` / `admin_write`.
- Reject-unknown validation:
  - collection workspace payloads use strict resource summaries,
  - detail template draft/save payloads use `DetailPageDocument` normalizer,
  - binding updates reject unknown fields and unsafe prop paths.
- Anti-abuse:
  - no public write endpoint,
  - sample entry preview cannot expose draft entries publicly without preview
    token/admin context,
  - generated links are safe relative admin/runtime URLs.
- Public-write hardening:
  - embedded public forms reuse existing nonce/captcha/access contracts.
- Secret handling:
  - secret-like fields are blocked or redacted in public bindings,
  - no CSRF tokens, preview tokens, provider keys, submissions, or secrets are
    stored in browser cache/debug payloads.
