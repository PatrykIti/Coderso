## Overview

Remove the frontend keyword gate as the primary router for `LLM Guide`.

When the assistant is in `LLM Guide` mode, user prompts should go to `/assistant/actions/plan` by default. The backend planner then decides whether the result is a CMS operation plan, read-only inspection, docs-style guidance response, or `needs_input`.

This prevents prompts like "sprawdz jakie ekrany customowe sa widoczne" from falling into `/assistant/chat` RAG only because the browser-side keyword list missed the phrasing.

## Sub-Tasks

No child task files.

## Architecture

Current problematic shape:

`AssistantPanel keyword check -> /assistant/actions/plan OR /assistant/chat`

Target shape:

`AssistantPanel in llm-guide mode -> /assistant/actions/plan`

The planner response decides:

- `inspection`: read-only candidate list,
- ready action plan: review/dry-run/execute,
- `needs_input`: disabled action controls and clarifying question,
- docs guidance response: non-executable answer generated by planner response contract from `TASK-178-03-04`.
