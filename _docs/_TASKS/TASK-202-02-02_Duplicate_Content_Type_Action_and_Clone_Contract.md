## Security Contract

- Visibility: internal admin action only.
- Auth model: unchanged admin session/API key.
- RBAC: `content:write`.
- CSRF: required for duplicate mutation.
- Rate-limit bucket: `admin_write`.
- Reject-unknown validation:
  - source id must be explicit,
  - target name/slug must be explicit or generated by the server and returned,
  - unknown fields are rejected by the existing validation layer.
- Anti-abuse:
  - entries, media, custom screens, listings, and taxonomies are not cloned,
  - clone keeps schema metadata but does not copy runtime records,
  - duplicate target must not overwrite an existing slug.

## Testing Requirements

- Duplicate action creates a schema-only copy.
- Target name/slug are unique and deterministic.
- Cache updates include list and new detail keys.
- Successful duplicate shows a shared-toast success message naming the new type.
- Failed duplicate keeps the current row/editor state and shows a redacted,
  user-readable error.
- Error path handles duplicate target slug cleanly.
- Server/domain tests prove entries, custom screens, taxonomies, listings, and
  other owner resources are not cloned.
- Route tests prove duplicate payload validation, conflict mapping, and response
  shape.
