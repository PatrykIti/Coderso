### Owned resources

Before work, assert lifecycle acceptance. Allocate and immediately register:

- exact provider/search/Figma synthetic upstream transports or terminal
  dependency-injection handles;
- exact reversible feature/provider/settings overrides;
- one supervised real Coderso host and readiness probes;

  database profile;
- one task-owned fixture namespace/ledger;
- one named browser transport/session;
- temporary private action-source/evidence workspace; and
- every fault-injection handle, preview session, and one-time bind-secret fixture.

Each `close()` is idempotent and each `proveAbsent()` checks the real process,
port, session, setting, row, object, asset, or hook. Shared lifecycle closes in
reverse order on success/failure. A factory that fails before registration
cleans its partial allocation itself.

Child environments are exact allowlists; never spread `process.env`. Provider
and Figma fixtures use synthetic non-secret credentials and the test dependency
injection seams delivered by terminal leaves; do not add a production fallback,
DNS override, arbitrary base URL, or live credential requirement.

### Worker operations and database safety

Register strict versioned operations for bounded baseline, fixture seed,
product-state inspection, fault arm/disarm, uncertain-result reconciliation,
cleanup, and post-cleanup absence. Each operation has exact profile/schema IDs,
stable source digest, byte limits, recursive validators, and bounded safe output.
Unexpected handler errors collapse to `operation_failed`; stdout is protocol
only.

Database mutations use the worker's transaction handle, exact owner provenance,
set-based bounded operations, `RETURNING` identity, FK-safe ledger waves, and a
post-commit absence read. No unordered child/parent `Promise.all`, broad
installation delete, table truncate, global client inside a transaction, or
one process/query is allowed. A mutation whose response is uncertain is never
replayed: dispatch a separate idempotent read and classify exact
pre/post/partial/foreign state, where partial/foreign is a hard failure.

API/storage/media cleanup remains with the owning API/storage/media service
when that boundary is part of the proof. Public/canonical promoted fixtures use
the native ownership ledger and restore exact baseline digests/cache/search
state.

### Browser plan and evidence

Build the ordered logical action plan first. Scenario changes, runtime DB/API
barriers, captured IDs/digests, and standalone screenshots create explicit
segment boundaries, so runtime barriers are never lost from the compiled
browser dispatch plan. Materialize action source before the
92 KiB per-action/96 KiB program checks and validate every returned frame.

Pre-navigation listeners, exact action/scenario IDs, bounded frame schemas,
first-failure stop, and serial dispatch are mandatory. Browser proofs return
safe booleans/counts/dimensions/ARIA/data values only—no cookies, headers,
tokens, DOM dumps, raw responses, authored private text, or internal IDs.

This suite does not claim resumable runtime scenarios. Every invocation runs
all 25 scenarios and canonical cleanup; there is no runtime scenario seal,
checkpoint, resume, or selective replay path. The post-run TASK-545 evidence
checkpoint is mandatory but resumes only reviewed evidence and terminal
metadata closeout; it never skips or replays product scenarios.

## Security Contract

- **Endpoint visibility:** this leaf adds no product endpoint. Tests call the
  terminal internal `/admin/api/assistant/*`, `/admin/api/designer/*`, Settings,
  Post/native routes, and the internal same-origin read-only Designer preview route.
  No public Agent/Figma/Designer write is introduced.
- **Auth model:** real authenticated Admin session with server-derived actor,
  auth epoch, Agent session ownership, Designer workspace ownership, and
  native resource identity. Preview requires that same Admin session plus its
  consumed one-time bind secret and terminal session/workspace/revision/digest/
  TTL binding; the path ID is not authorization and never authenticates an Admin
  write.
- **RBAC:** positive and negative paths cover `assistant:use`,
  `assistant:research`, `designer:read`, `designer:write`,
  `designer:promote`, `settings:read`, `settings:write`, `content:read`,
  `content:write`, `content:publish`, and every exact staged-plan native
  permission. No wildcard role masks a missing mapping. Denial occurs before
  provider, existence-sensitive, staging, or canonical work.
- **CSRF:** every internal POST/PUT/PATCH/DELETE uses the shared valid CSRF token;
  missing/invalid token negatives prove zero facade/service/provider dispatch.
  GET/HEAD remain side-effect free. OAuth state/PKCE and idempotency do not
  replace CSRF.
- **Rate-limit buckets:** assert exact `assistant`, `assistant-research`,
  `private-input-upload`, `designer-generation`, `designer-preview`,
  `designer-promotion`, `designer-figma`, `admin_read`, and `admin_write`
  assignments plus provider/actor/workspace/installation limits. Missing/weaker buckets
  fail; bounded retry metadata never creates a loop.
- **Reject unknown:** route params/query/body/multipart, provider/search/Figma
  fixtures, capability facts, worker frames, operation input/output, browser
  actions/proofs, cleanup receipts, screenshots, and reports recursively reject
  unknown keys and enforce exact count/byte/depth/ID limits.
- **Anti-abuse:** this leaf creates no public write; nonce, HMAC/signature, and
  reCAPTCHA are therefore not added. Promoted public Form writes must retain
  their native nonce/signature/CAPTCHA policy, strict validation, and bucket.
  Preview remains internal same-origin GET/HEAD-only, session-bound,
  short-lived, no-store/noindex, redirect-safe, revocable, and bounded.
- **Secrets/privacy:** use synthetic fixtures. Keys, OAuth code/state/verifier/
  tokens, session/CSRF/cookies, raw prompts/transcripts/attachments, search/page/
  provider bodies, source/private URLs, staged/native payloads, storage keys,
  SQL/binds, PII, and raw logs/DOM never enter browser persistence, screenshots,
  task/changelog prose, reports, or audit metadata.
- **Cleanup/transactions:** exact owner provenance, bounded set-based FK waves,
  transaction-handle discipline, post-commit absence, provider/settings restore,
  cache/search/outbox reconciliation, and uncertain-result read reconciliation
  apply. Never truncate, broad-delete the installation, clear another user's state, or
  replay an uncertain mutation.
