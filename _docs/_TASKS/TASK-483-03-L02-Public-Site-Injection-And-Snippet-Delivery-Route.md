## Overview

- **Goal:** Inject the tracking snippet into the published-site document and
  serve it, so real visits reach the collector. The snippet is referenced from
  the rendered HTML with a fresh per-render nonce.
- **Owning module(s) to extend:**
  - `core/site/renderPublicPage.tsx` — `renderDocument()` appends the analytics
    `<script>` (inline IIFE) before `</body>` via the existing
    `renderBodyScripts` seam (it already collects body scripts at line ~174).
  - `core/server/publicSite.tsx` — pass a per-render `analyticsNonce` into the
    render path and dispatch the script-delivery route inside
    `handlePublicRequest`.
- **Source-of-truth docs:** `_docs/SECURITY_SPEC.md`, `_docs/CMS_API.md`.
- **Out-of-scope:** the snippet/payload builder (L01), the collector (TASK-483-02).

## Security Contract

- **Endpoint visibility:** the inline snippet is part of the public HTML. If a
  separate static asset is preferred, expose `GET /_analytics/a.js` (public,
  `Bun.file`-served, immutable cache headers); the nonce is then passed as a
  query param minted per page render, not baked into the cached file.
- **Auth model / RBAC / CSRF:** N/A (public read of a static script).
- **Rate-limit bucket:** `public_read` if a static route is added; the inline
  variant adds no new endpoint.
- **Validation schema-owner module:** N/A (no inbound payload here).
- **Anti-abuse controls:** the nonce embedded per render is generated by
  `createBeaconNonce()` (TASK-483-02-L01) at render time so each page issues a
  fresh, short-TTL token; never reuse a single global nonce.
- **Secret/PII handling:** the snippet contains no secret. Honor a global
  "analytics enabled" setting and a DNT/consent toggle: when analytics is
  disabled in settings, do not inject the script at all. Injection must not break
  CSP — if a nonce-based CSP is active, reuse the document CSP nonce on the
  `<script>` tag.

## Implementation Pseudocode

```ts
// core/site/renderPublicPage.tsx — renderDocument(...)
const bodyScriptsHtml = renderBodyScripts ? renderToString(<>{renderBodyScripts()}</>) : "";
// renderBodyScripts now also yields:
//   analyticsEnabled ? <script dangerouslySetInnerHTML={{ __html: trackingScript }} /> : null

// core/server/publicSite.tsx — when building render options:
const analyticsEnabled = await isAnalyticsTrackingEnabled();   // settings-driven
const trackingScript = analyticsEnabled
  ? buildTrackingScript({ nonce: createBeaconNonce(), collectPath: ANALYTICS_BEACON_PATH })
  : null;
// thread trackingScript into renderPublicPage options -> renderBodyScripts

// Optional static delivery route inside handlePublicRequest:
if (url.pathname === "/_analytics/a.js") {
  return new Response(Bun.file(ANALYTICS_SNIPPET_FILE), {
    headers: { "content-type": "text/javascript; charset=utf-8",
               "cache-control": "public, max-age=86400, immutable" },
  });
}
```

Data flow: each public page render mints a nonce, builds the script (L01), and
injects it before `</body>`; the browser runs it and beacons to the collector.
When tracking is disabled in settings, no script is emitted.

Error handling: snippet build/inject failures must never break page rendering —
wrap in a guard that logs a warning and renders the page without analytics
(degrade gracefully, like the existing booking/script seams).

Regression-test shape:

```ts
// Vitest ui-integration (renderToString is Bun-free):
// tests/vitest/ui-integration/publicAnalyticsInjection.test.tsx
test("enabled: page HTML contains the beacon script with a nonce", async () => {

});
```
