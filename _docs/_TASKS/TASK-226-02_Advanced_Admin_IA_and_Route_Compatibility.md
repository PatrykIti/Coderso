## Overview

Move the technical/admin module IA from a `Coderso` group to an `Advanced`
group. `Coderso` is the product brand; `Advanced` is the sidebar group and
canonical admin namespace for higher-complexity modules such as Engine, Entries,
Widgets, Forms, Listings, Booking, Commerce, Reviews, Popups, and Solution Kits.

The implementation must preserve existing bookmarks and generated links through
`/admin/coderso/*` aliases while emitting `/admin/advanced/*` as the canonical
path after this task.

## Security Contract

- Visibility: internal admin UI and internal assistant/runtime context.
- Auth model: existing authenticated admin session / admin API key path.
- RBAC: unchanged per existing module route.
- CSRF: unchanged for admin/internal writes.
- Rate-limit bucket: unchanged.
- Reject-unknown validation:
  - route aliases must not loosen payload validation,
  - assistant schema must strictly version or explicitly adapt legacy
    `codersoModule` fields.
- Anti-abuse:
  - no public redirect endpoint,
  - no open redirect behavior,
  - no path traversal or arbitrary route passthrough,
  - legacy aliases must normalize to known Advanced routes only.
