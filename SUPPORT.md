# Support

Coderso support requests should be clear, reproducible, and routed through the
least public channel that fits the issue.

## Where To Ask

- Usage questions: use GitHub Discussions when they are enabled. If Discussions
  are not available, open a repository issue and label it as a question or
  support request.
- Bug reports: open a repository issue with a reproducible case.
- Feature requests: open a repository issue or Discussion with the product
  outcome, user problem, and expected workflow.
- Security issues: do not open a public issue. Use GitHub Private Vulnerability
  Reporting or email `security@paktryiti.pl`; see `SECURITY.md`.

## Before Opening A Request

- Search existing issues, pull requests, and documentation.
- Check the current root `README.md`, `AGENTS.md`, and relevant files in
  `_docs/`.
- Reproduce the issue on the current branch or state the exact commit, release,
  or deployment where it happens.
- Remove secrets, tokens, database URLs, private keys, and customer data from
  logs or screenshots.

## What To Include

- A short summary of the problem or request.
- The expected behavior and the actual behavior.
- Steps to reproduce, including commands and URLs when relevant.
- Environment details: operating system, Bun version, Node version if relevant,
  database provider, and browser for UI issues.
- Relevant logs, stack traces, screenshots, or failing test output.
- Whether the issue affects beginner-facing UI, advanced platform behavior,
  runtime behavior, plugin behavior, or release automation.

## Scope Of Support

Project support covers Coderso repository behavior, documentation clarity,
development workflow, security reporting, and release automation. Custom
deployments, private infrastructure, third-party service outages, and local
environment differences may require a minimal reproduction before they can be
investigated.

## Response Expectations

Unless a paid or written support agreement exists, community support is provided
on a best-effort basis. Clear reproduction steps and small examples make support
requests faster to triage.
