# Support

Thanks for using or exploring Coderso.

Coderso is built to help people create useful websites, content systems, and
digital products. Questions, bug reports, feature ideas, and documentation
feedback are welcome.

Support works best when requests are clear, kind, reproducible, and routed
through the least public channel that fits the issue.

## Where to Ask

- Usage questions: use GitHub Discussions when they are enabled. If Discussions
  are not available, open a repository issue and label it as a question or
  support request.
- Bug reports: open a repository issue with a reproducible case.
- Feature requests: open a repository issue or Discussion with the product
  outcome, user problem, and expected workflow.
- Documentation issues: open an issue with the unclear page, missing detail, or
  suggested improvement.
- Security issues: do not open a public issue. Use GitHub Private Vulnerability
  Reporting or the security contact listed in `SECURITY.md`.

Beginner questions are welcome. If something feels confusing, that is useful
feedback for the project.

Email: support@coderso.dev

## Before Opening a Request

Before opening a request, please try to:

- Search existing issues, pull requests, and documentation.
- Check the current root `README.md`, `AGENTS.md`, and relevant files in
  `_docs/`.
- Reproduce the issue on the current branch or state the exact commit, release,
  or deployment where it happens.
- Remove secrets, tokens, database URLs, private keys, customer data, and private
  infrastructure details from logs or screenshots.

## What to Include

Please include:

- A short summary of the problem or request.
- The expected behavior and actual behavior.
- Steps to reproduce, including commands and URLs when relevant.
- Environment details:
  - operating system,
  - Bun version,
  - Node version if relevant,
  - database provider,
  - browser for UI issues.
- Relevant logs, stack traces, screenshots, or failing test output.
- Whether the issue affects:
  - beginner-facing UI,
  - advanced platform behavior,
  - runtime behavior,
  - plugin behavior,
  - store behavior,
  - release automation,
  - documentation.

The more focused the reproduction is, the easier it is to help.

## Scope of Support

Project support covers:

- Coderso repository behavior,
- documentation clarity,
- development workflow,
- security reporting,
- release automation,
- reproducible bugs,
- contribution guidance.

Custom deployments, private infrastructure, third-party service outages, and
local environment differences may require a minimal reproduction before they can
be investigated.

## Response Expectations

Unless a paid or written support agreement exists, community support is provided
on a best-effort basis.

Clear reproduction steps, small examples, and respectful communication make
support requests faster to triage.

## Community Tone

Please be patient and kind when asking for help or helping others.

Coderso is built with the belief that useful software should make people’s work
easier, not make them feel small for asking questions.
