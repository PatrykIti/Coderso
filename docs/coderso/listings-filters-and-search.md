# What Is It

Listings, Filters, and Search are the query and discovery surfaces for turning
structured records into browseable, filterable, and searchable public
experiences.

# When To Use

Use these screens when you already have structured data in Engine and Entries
and need a discovery experience instead of isolated detail pages only.

# Step By Step

1. Confirm the source records and fields in Engine and Entries.
2. Build or refine listing queries and templates.
3. Add filters and search behavior that match real user decision paths.
4. Validate the final discovery flow with representative records and terms.

# Examples

- A services directory uses listings plus filters for category and location.
- A clinic site exposes searchable doctor and service discovery.
- A commerce-support catalog uses listings to help users find offer bundles or
  supporting product information.

# Common Mistakes

- Building listings before the underlying record model is stable.
- Adding filters that do not map cleanly to real fields or user intent.
- Treating search as a replacement for good listing and taxonomy design.
