# What Is It

Dashboard is the operational overview for the admin workspace. It surfaces
high-level activity, site health, security status, and recent changes so you
can decide what needs attention before drilling into specialist screens.

# When To Use

Use Dashboard at the start of a work session, after a deployment, or when you
need a quick answer to the question, "What changed and what needs action?"

# Step By Step

1. Review health and status cards for security, availability, and maintenance
   signals.
2. Check recent edits to see what content or configuration changed recently.
3. Use the summary information to decide whether you need Pages, Media,
   Settings, or a Coderso module next.
4. Treat Dashboard as a triage screen, not the place where deep editing
   happens.

# Examples

- An admin opens Dashboard after a release to confirm that no obvious health
  warning appeared.
- A content lead checks recent edits before continuing a publishing workflow.
- A support owner uses Dashboard to decide whether to inspect audit logs,
  access logs, or settings changes.

# Common Mistakes

- Expecting Dashboard to expose every low-level detail instead of using it as a
  summary surface.
- Skipping Dashboard entirely when troubleshooting a broad operational issue.
- Treating it as a reporting tool instead of a decision and navigation tool.
