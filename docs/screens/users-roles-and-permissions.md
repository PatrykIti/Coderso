# What Is It

Users, Roles, and Permissions are the access-control screens for inviting
people, defining responsibility boundaries, and controlling which admin actions
each role can perform.

# When To Use

Use these screens when onboarding staff, splitting responsibilities across
teams, or reducing the blast radius of sensitive actions such as security,
settings, or destructive content changes.

# Step By Step

1. Define or review the available roles and permission matrix.
2. Invite users or edit existing user access.
3. Give each user the minimum role needed for their actual work.
4. Revisit permissions after enabling new Coderso modules or operational
   surfaces.

# Examples

- Editors get content-oriented permissions without access to security settings.
- Operations staff get audit and access-log visibility without broad publishing
  power.
- Commerce or booking owners receive access only to the modules they actively
  manage.

# Common Mistakes

- Reusing one broad admin role for every user.
- Forgetting to review permissions after adding new modules or integrations.
- Using user-level exceptions instead of maintaining clear role definitions.
