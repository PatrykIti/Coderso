# What Is It

Pages, Preview, and Page Editor cover the main page-management workflow: create
pages, edit content and layout, review device-specific presentation, and check
the public-facing preview before publishing.

# When To Use

Use these screens when you are building landing pages, legal pages, marketing
pages, or any custom page that is not better modeled as a structured record.

# Step By Step

1. Start in the Pages list to create, filter, or review existing pages.
2. Open Page Editor to adjust content, structure, widgets, SEO, and page-level
   settings.
3. Use preview surfaces to verify how the page behaves before publishing.
4. Return to the list to manage publishing state, revisions, or page-level
   actions.

# Examples

- A marketing team creates a campaign page, reviews the preview, and publishes
  after SEO checks.
- An operations user updates a service information page without changing any
  structured data model.
- A designer uses the editor and preview together to validate layout changes
  before go-live.

# Common Mistakes

- Using pages for highly structured, repeatable records that should live in
  Coderso Engine and Entries.
- Publishing before previewing responsive behavior and linked assets.
- Forgetting that page settings and SEO can matter as much as visible content.
