## SHARED-SINGLETON constraint (drives the test split)
The dev server (:5173 admin / :3000 front) and Postgres are **singletons** — parallel
worktree agents can NOT each run `coderso-dev-core-host`. Therefore:
- **Per implementing agent (in worktree):** static validation only —
  `bun --cwd core lint`, `bun --cwd core lint:types`, and the **targeted Vitest** suites
  for the touched files (Bun-free; no live server/DB).
- **Per WAVE integration (me, on the merged branch):** the heavy gate — full `bun test`
  (runtime) + full `vitest`, DB-backed suites, `bun run gates:coderso`, then bring up the
  server and run a `playwright-cli` smoke of the changed screens.

## Testing protocol (standing rules — apply at every runtime/playwright step)
- Server is started by the helper command **`coderso-dev-core-host`**.
- **ALWAYS check the server is up before any runtime/playwright smoke.** Hit
  **http://coderso-a.localhost:5173/admin/** — a **white/blank page (or refused)** means the
  server is **down** → re-run `coderso-dev-core-host` → re-check before proceeding.
- Front end: **http://coderso-a.localhost:3000**.
- A full `bun run test` / `bun test` **resets the CMS setup wizard** on next first launch —
  it must be **clicked through** before admin/front behave normally.
- Credentials are in **`.env`**. Before any DB/settings test: `set -a && source .env && set +a`.
- Use the installed **`playwright-cli`** terminal command (default chromium; no `chrome` channel).
- **All bun + vitest suites must pass.** Run the full relevant suites as the FINAL gate of
  every implementation/wave (slow but mandatory); state clearly anything skipped/blocked.
- Follow `_docs/TESTING_STRATEGY.md` lanes; add/extend tests in the correct lane per change.
